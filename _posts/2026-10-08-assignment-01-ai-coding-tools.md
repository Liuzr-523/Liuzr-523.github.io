## 1. 老师要求做什么

任务是：从 **Trae / WorkBuddy / Codex / Claude** 里挑一个装上、真用一次，然后讲清楚用它会了什么、卡了什么。

我理解这次要验收的不是「装没装上」——下载安装谁都会。真正要看的是**有没有让它替你去完成一件原本麻烦的事**，以及你能不能分辨出它给你的东西哪些是对的、哪些是它瞎编的。

所以我没打算交一张「安装成功」的截图，而是把整件事摊开：什么时间、用什么工具、干了什么、在哪一步被挡住。

## 2. 我实际做了什么

环境：macOS + zsh，Node v22.22.2，miniconda Python 3.14.7。

### 2.1 四个都上手试过

最先认真用的是 Trae，9 月 21 日到 24 日，任务列表里攒了一串：

![Trae SOLO 的任务历史：从 NumPy 线代到寻找 Claude 中文补丁](/assets/img/hw01/trae-solo-tasks.png)
*图1 · Trae SOLO CN 的任务列表，时间跨度 9-21 ~ 9-24*

这张表能看出两件事：

- **它确实被用来干活了**，不是装上摆着 —— NumPy 与线性代数、代码写法对比分析、py 答疑、Mac 上 Keka 压缩包的解读，都是真实的课程或工具需求
- **它是断点式的**。9-21 那个「NumPy与线性代数」后面标着**任务中断**，说明当时没跑完；9-24 那天又重新起了一串

这条时间线后来成了我选工具的判断依据：我要的不是「能答问题」，是「能陪我把一件事做完」。

### 2.2 最后落在 WorkBuddy 上

只有第三行能一口气做完「改文件 → 跑命令 → 看结果 → 再改」这个循环。

## 3. 卡在哪，怎么绕过去的

### 坑一：Claude 的汉化，我改坏了两次

我想给 Claude 桌面版装简体中文语言包。装完之后应用直接打不开，而且不是一次 —— 中间留了两个备份文件夹，日期分别是 `20260924` 和 `20260927`，说明**至少失败过两回**。

![Claude 桌面版界面](/assets/img/hw01/claude-desktop.png)
*图3 · Claude 桌面版，左侧 Tasks 里还留着「Claude 语言包 README 翻译」*

排查过程：

- **我以为是**：语言包版本下错了
- **实际是**：Mac 上替换应用内部文件之后**必须重新签名**，否则系统的签名校验直接让应用闪退。这一步没有任何界面提示

  ```bash
  codesign --force --deep --sign - "/Applications/Claude.app"
  ```

- **教训**：动应用内部文件的三步铁律 —— 先备份、再替换、最后补签名。那两个备份文件夹就是学费

另外图3 左下角那个「网关」不是官方登录，是我把 Claude 桌面版接到了第三方模型服务上，界面上显示的 `deepseek-v4-pro` 就是当时用的模型。这一步是照着文档自己配出来的，虽然不算「用 Claude」，但配置过程本身挺折腾。

### 坑二：网站推上去了，页面却不更新

- **现象**：文件都推到 GitHub 了，刷新网页还是老样子
- **原因**：换了主题之后构建方式变了，仓库 Settings → Pages 里的 Source 必须切成 **GitHub Actions**，不能再是「从 main 分支读」
- **排查位置**：仓库的 Actions 标签页，看那次构建有没有报红

这条如果不动手，光看教程是学不到的 —— 教程默认你没换过主题。

## 4. 工具替我做了多少，我自己做了多少

**它替我干的**：写那十几份模板文件的样板代码、记住 Jekyll 各种配置的写法、把重复的格式统一。这些我查文档也能做，但会花掉一个下午。

平时零碎的答疑也在用，比如手机上随手问：

![手机端 ChatGPT 的历史记录](/assets/img/hw01/chatgpt-mobile.jpg)
*图4 · 手机端 ChatGPT 的历史，NumPy 矩阵表示、random 库用法都是课上要用到的*

**我必须自己拍板的**：

- **「作业怎么交」这件事的设计是我提的**。老师说想要过程记录，但没说怎么留。我用 `hw_*` 那套字段把每次作业变成结构化数据，是为了让机器以后能自动统计 —— 这个需求不是它想的，是我推出来的
- **判断它给的东西对不对**。它第一次给的配置里引用了一个我压根没装的插件，页面会直接报错，是我核出来的
- **上面两个坑的最终解释**，是我复盘之后整理出来的，不是它原始的输出

**我学到的**：

- 跟 AI 协作里最值钱的不是让它写代码，是**把需求拆到它能执行的粒度**。我说「帮我建个作业系统」，它返回一堆泛泛的东西；我说「每次作业是一篇文章，front matter 里放 seq / due / tool / status 五个字段，再写个页面把它拉成表」，一次就对了
- **它抽风是有征兆的**：答非所问、开始重复、编函数名。出现这三种直接打回，别顺着往下聊

## 5. 这次的收获 & 下次要改的

收获：第一次真切体会到「把需求说清楚」是硬技能，不是鸡汤。同一个工具，我第一版说法和第四版说法的产出质量差了一个量级。另外 Trae 那份列表里的「任务中断」也提醒我 —— 工具用得再顺，断在半路的东西不会自己变完整。

下次要改的：动手前先花两分钟写清楚「这次要什么、哪些东西不许动」，别让它自由发挥。
